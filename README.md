# astrbot-plugin-apimode

本地模型 / 第三方 API 的切换与用量管理插件，用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot)。

它做的是"运维层"的事：在不重启 QQ、不重新扫码的前提下，切换机器人背后的模型来源，控制 token 额度，并对指定群的输出做审查。

## 功能

- **模式切换**：`/切换 api 本地` 将模型切到本地 llama.cpp（8080），`/切换 api 第三方` 切到 OpenAI 兼容的第三方 API（如 DeepSeek）。切换由后台定时器落实，期间会停/起对应服务。
- **token 预算**：注入 LLM 请求前检查当日用量，超限则拦截；响应后累计 token 数。
- **省 token**：`/省token on|off` 控制是否压缩发给模型的上下文。
- **按群审查**：`/审查 on|off` 对指定群的模型输出做后置审查（仅第三方模式生效）。
- **用量查询**：`/用量` 看当日已用 token。
- **判官开关**：`/判官 状态` 看第三方判官的开关、条数前处理、概率闸、话段聚合、在途硬锁与今日 tokens；`/判官 开关 on|off`、`/判官 预算 on|off`、`/判官 概率 on|off`、`/判官 话段 on|off`、`/判官 锁 on|off`、`/判官 等待 N`、`/判官 限额 N` 改配置（写 `data/judge_api.json`，无需重启）。

以上管理命令仅限管理员。

## 状态文件

状态写在 AstrBot 数据目录下的 `data/api_mode.json`：

```json
{
  "mode": "local | third_party",
  "save_token": true,
  "daily_limit": 200000,
  "used": { "date": "20261118", "tokens": 0 },
  "review_groups": { "942316942": true }
}
```

> 注意：本插件的状态文件只是记账。**模式的唯一真相是 AstrBot 自身的 `provider_id` 配置**，本插件切换时同步修改它；手动改 `api_mode.json` 不会真正生效。

## 判官模块（描述文档）

"判官"负责回答一个问题：**这条群消息，机器人要不要接一句？** 它只在**第三方模式**下启用；本地模式（`local-llama`）继续走 8082 小模型那一套，代码路径与最初版本一致。

判定链路本身在主仓 AstrBot 补丁 `builtin_stars/astrbot/group_chat_context.py` 里（`need_active_reply` / `_need_active_reply_api` / `on_req_llm` / `note_message_sent`），本插件只负责开关、记账和 `/判官` 命令。

### 1. 两条通道：锁必须装在请求入口

| 入口 | 触发条件 | 走哪条路 | 判官能管到吗 |
|---|---|---|---|
| 主动接话 | 群里正常发言 | `need_active_reply()` → 判官判定 | 能，全部规则都在这条路上 |
| @ / 唤醒前缀 | `is_at_or_wake_command` | AstrBot 内置回复通道 | **不能**，`need_active_reply` 第一句就 `return False` |
| 明确指令 | `/reset`、`/记忆` 等 | 各插件的 command handler | 不需要管 |

第二条是坑：@ 它时**根本不经过判官**，所以无论在 `need_active_reply` 里加多少锁，都挡不住"回复到一半又被 @ 一次"的双发。正确位置是 `on_llm_request` 钩子——在那里 `event.stop_event()` 会让 pipeline 直接放弃本次 LLM 调用，一分钱 token 都不花。

### 2. 判定顺序（主动接话通道）

从上到下，越靠前越省 token，命中就结束：

| 顺序 | 判断 | 成本 | 命中结果 |
|---|---|---|---|
| 0 | 空消息、`/` 或 `／` 开头的指令 | 0 | 不接（也不计入回复预算） |
| 1 | **召唤词**（消息里含 `bot_names` / `summon`） | 0 | 直接接，但不越过"在途"和 `summon_gap` |
| 2 | **回复在途**（生成中 / 分段发送中） | 0 | 不接 |
| 3 | **刚回过话的冷却**（`reply_gap`） | 0 | 不接；叫名字放行，带脏话放行给判官 |
| 4 | **条数限制前处理**（`budget_gate`） | 0 | 超了不接 |
| 5 | 免打扰词 / 必答词 / 必答正则 / 追问正则 | 0 | 按规则不接或直接接 |
| 6 | **话段复用**（这一段判过或回过了） | 0 | 不接（省 token） |
| 7 | 过短（按合并后整段算）、复读 | 0 | 不接 |
| 8 | **相似去重**（`dup_window` / `dup_ratio`） | 0 | 不接 |
| 9 | 判官关闭（`enable: false`） | 0 | 按 `fallback_chance` 兜底 |
| 10 | **调判官模型** | ~130 tokens | 判 1 接、判 0 不接并标记本段已判 |
| 11 | 概率闸（`use_reply_chance`，默认关） | 0 | 拦截后不接 |
| 12 | 判官调用失败 / 超日限额 / 熔断 | 0 | 按 `fallback_chance` 兜底，不硬中断 |

两条容易忽略的细节：

- **第 4 步在第 10 步之前**。条数超了就不该再花 token 去问模型，所以限制是"前处理"而不是"回完再算"。
- **判 0 也会记一段**（`_mark_burst("judged")`）。否则同一口气里的后续消息会把同一个问题再问一遍模型，白花钱。

### 3. 话段聚合：一句话拆成三句发

很多人习惯把一句话拆成两三段发："我跟你说个事" → "我买了新相机" → "你猜多少钱"。逐条判定会有两个后果：漏判（前两句单独看没意义）和连发（三句各自判定，各自都觉得该回）。

做法是**等这一口气说完，只判一次**：

| 字段 | 默认 | 作用 |
|---|---|---|
| `burst_enable` | true | 总开关，关掉＝退回逐条判定 |
| `burst_settle` | 3.5 | 判定前先等这么久；期间又来消息就放弃，交给最新那条 |
| `burst_gap` | 15 | 两条消息间隔小于它算同一段；冷场超过它算新话题 |
| `burst_reuse` | 45 | 这一段**判过或回过后**不再送判官（省 token） |
| `summon_gap` | 4 | 叫名字不吃冷却，但几秒内连叫只应一次 |

实现上有一个必须记住的点：**到达时间戳在锁外写，等待也在锁外做**。如果把 `await asyncio.sleep()` 放在 `async with self._get_lock(umo)` 里面，后续消息的 `handle_message` 会被同一把锁挡在门外，"期间来了新消息"这个条件永远不成立——那段"放弃"逻辑会变成死代码，实际效果只是每条消息都白等几秒。

### 4. 在途硬锁：回复期间完全锁死

要挡的是"回复正在生成或正在分段发送时，又来一条该回的消息"。难点在于时间基准：`on_llm_response` 触发时只是**模型生成完**，消息还没开始发。

所以是三层：

**第一层 · 生成完先按上沿顶住（兜底）**

`note_bot_reply()` 用 `_estimate_send_seconds(text, upper=True)` 算最坏情况，把在途锁设到那一刻：

```text
human 模式每段：min((0.45 + 字数/7) × 1.35 + 1.8, 5.5) + 0.4s 网络
log 模式每段  ：(log(字数+1, base) + 0.5) + 0.4s
random 模式   ：取区间上限 + 0.4s
```

| 回复 | 均值估算 | 上沿估算 |
|---|---|---|
| 三段各 5 字 | 约 5.0s | 约 11.3s |
| 单句 10 字 | 约 2.4s | 约 4.7s |

**锁"正在发送"必须取上沿**：AstrBot 的抖动是 `uniform(0.75, 1.35)`，取均值意味着有一半概率估短，估短就会在真正发完之前放开锁——而"回复快出来时又喊一声"恰好是高频时段。

**第二层 · 真实发完立刻收敛（主信号）**

AstrBot 的 `after_message_sent` 在所有分段和它们之间的 `sleep` 之后才触发，就是"用户已经看到消息"的那一刻。`note_message_sent()` 在这里做三件事：

```python
_inflight_until = 0                    # 立刻释放在途
_cool_until     = now + reply_gap      # 冷却从真正发完起算
_last_bot_span  = (start, now)         # 发言区间收敛到真实时刻
```

`after_message_sent` 对**所有**发送都会触发，包括别的插件推送的消息，所以它带一个 `owned` 参数：只有当这条发送由本插件的判定引起时才允许释放锁，否则只记日志不动状态。另外，若当前没有在途锁，这个钩子直接返回，不会顺手给群加一段冷却。

**第三层 · 请求入口硬挡 @ / 唤醒前缀**

`on_req_llm()` 里，满足「@ 或唤醒前缀 + 群消息 + 第三方模式 + `inflight_lock` 开 + 不是指令」时：

- 有在途锁 → `event.stop_event()`，pipeline 不调模型，日志 `在途硬锁，@/唤醒被挡`
- 没有在途锁 → 这次 @ 触发的回复**自己先占住**在途锁（`inflight_ttl`），否则它分段发送的那几秒里，别人再喊一声又会被当成新话回一条

三个防误伤：

1. 同一条消息可能多轮进这个钩子（工具调用循环），用 `_judge_inflight_owned` 只处理第一轮；
2. `@ 它 + /reset` 这类明确指令不受影响（`handlers_parsed_params` 非空就跳过）——聊天锁不该吞指令；
3. 只对群消息生效，私聊不参与。

兜底：生成或发送失败、`after_message_sent` 没来，`inflight_ttl`（45s）到期自动放开，不会把群永久锁死。

### 5. 强触发：规则和判官各管一段

冷却期和话段复用期都不是硬墙，但"破例"分两种性质：

| 情况 | 谁来判断 | 结果 |
|---|---|---|
| 含 `bot_names`（阿灰/灰灰/…）或召唤词 | 规则，0 token | **直接接**。明确点名，没什么可犹豫的 |
| 含 `break_words`（脏话） | 判官，约 130 tokens | **只放行，不定罪**：交给判官结合上下文判断在骂谁 |
| 纯脏话、上一条不是它说的、也没第二人称 | 判官 | 判 0，标记本段已判，不再花钱 |

规则只能看出"这句有脏话"，看不出"这句骂谁"。"你傻逼吧"可能是骂它，也可能是骂刚说话的那个群友。所以命中脏话时会在提示词末尾追加一段：

```text
注意：这句带脏话。先判断它在骂谁——
如果是在接你刚才说的「……」，或者用「你」指的是你，回 1；
如果明显在骂群里另一个人、跟你无关，回 0。
```

判官能看到 `{recent}` 和 `{last_bot}`，这是它比规则强的地方。多花的那点 token 只在出现脏话时产生，频率很低。

判断"上一条是不是它说的"用**发言区间**（`_last_bot_span` = 开始 ~ 发完）而不是单个时间戳：它一句话分几段发、中间隔好几秒，只记一个点会漏掉"发送期间插话"的情况。

### 6. 状态与生命周期

| 项 | 说明 |
|---|---|
| 存储 | 全部在内存，按 `umo`（会话唯一标识）分键，多群互不干扰 |
| 锁 | 判定按群串行（`_get_lock(umo)`），并发消息排队，后到的能看到前一个已认领 |
| 重启 | 状态清空，不会把"冷却"写进配置 |
| 本地模式 | 零侵入：`note_bot_reply` / `note_message_sent` / `on_req_llm` 三个入口都先判模式并早退，一个状态都不写 |

### 7. 兼容性

| 场景 | 会不会被误伤 | 原因 |
|---|---|---|
| @ 它 | 不会 | 走内置通道，`need_active_reply` 早退；只有"正在回复时"才被硬锁挡 |
| 其他插件（指令、工具） | 不会 | `on_message` 优先级最低（`maxsize - 2`）且从不 `stop_event()`；各插件的 handler 按自己的注册执行 |
| 话段聚合/冷却 | 只影响"要不要主动插话" | 不改变任何插件的返回值 |
| 插件主动推送的消息 | 不进冷却 | 只有本插件 `owned` 的发送才会释放锁、起冷却（取舍：宁可少挡，不误挡） |
| `/` 开头指令 | 直接跳过 | 不花 token，也不计入回复预算 |
| 改了 `segmented_reply` | 估算跟着变 | 分段配置按 mtime 缓存，下一条回复生效；改成 `random` 只能估中值，精度下降 |

### 8. 日志关键字

日志前缀统一是 `group judge |`，按这几条能直接看出走了哪个分支：

| 日志 | 含义 |
|---|---|
| `话段未说完，交给最新一条` | 拆句合并生效，本条让位 |
| `同话段已judged/answered，不再送判官` | 省 token 生效 |
| `点名打破冷却(剩Xs)` / `话段内点名，打破复用` | 叫名字破例 |
| `脏话待判(剩Xs)，交给判官看骂谁` | 脏话放行，由判官判归属 |
| `连发抑制(剩Xs)` / `回复在途` | 被冷却或在途挡住 |
| `召唤词但回复在途` / `召唤词间隔过密` | 唤名被限流 |
| `发送耗时上沿 Xs，等真实发完信号收敛` | 生成完，在途锁按上沿顶住 |
| `发送完成，冷却从此刻起算 Ns` | 真实发完信号到了 |
| `在途硬锁，@/唤醒被挡(剩Xs)` | 回复期间的 @ 被挡（本模块的核心目的） |
| `唤醒/点名已占在途锁` | @ 触发的回复自己占位，防它发送期间被再喊一次 |
| `API verdict=1 tokens=133` | 判官实际调用与消耗 |

### 9. 调参对照

| 症状 | 改哪个 |
|---|---|
| 拆句发的内容被漏掉 | `burst_settle` 调大（4~5），或 `burst_gap` 调到 20 |
| 回得慢、像在等 | `burst_settle` 降到 2.0（别低于 2，短于人类的换行间隔） |
| 还是连发 | `reply_gap` 加到 10、`dup_ratio` 降到 0.6 |
| 明显不理人 | `burst_reuse` 降到 20，或把群里常用叫法加进 `bot_names` |
| 叫了名字没应 | 检查 `bot_names` 是否含这个叫法；`inflight_lock` 只在真正发送期间挡 |
| 太省 token、误判偏多 | `/判官 限额` 放宽，`burst_reuse` 降低 |
| 完全退回逐条判定 | `/判官 话段 off` |
| 回复期间允许 @ 插队 | `/判官 锁 off` |

### 10. 搬到别的项目要抄什么

这套机制不依赖本项目的目录结构，最小可复用集是：

1. **两个纯函数**：`_estimate_send_seconds(text, upper)` 和 `_split_segments(text, seg)`——只读 AstrBot 的 `segmented_reply` 配置，不碰机器人状态；
2. **三个钩子**：`on_llm_request`（入口硬锁）、`on_llm_response`（生成完按上沿占位）、`after_message_sent`（真实发完收敛）；
3. **状态按会话分键**：`_inflight_until` / `_cool_until` / `_last_bot_span` / `_burst` 全部以 `umo` 为键，重启即清空。

顺序上的关键不变量：**占位（生成完）→ 收敛（真实发完）→ 释放；判定前先看占位，占位时不花 token，也不管消息是不是 @ 或唤醒前缀。**

## 判官配置（`data/judge_api.json`）

`/判官` 命令改的是这份文件，和上面 `api_mode.json` 那份记账文件无关。完整字段见
[`judge_api.example.json`](judge_api.example.json)，常用几项：

| 字段 | 默认 | 作用 |
|---|---|---|
| `enable` | true | 第三方判官总开关；关掉退回「规则 + 概率」 |
| `api_base` / `api_key` / `model` | — | 判官模型；`api_key` 留空则沿用主模型（deepseek provider）的密钥 |
| `prompt` | 内置 | 判定提示词，必须含 `{message}`；可选 `{recent}` / `{last_bot}` |
| `recent_max` / `recent_chars` | 15 / 250 | 上下文条数与单条截断，直接决定 token 量 |
| `max_tokens` / `temperature` | 2 / 0 | 只要一个 `1` 或 `0` |
| `budget_gate` | true | 条数限制前处理，超预算不调模型 |
| `use_reply_chance` / `reply_chance` | false / 1.0 | 判官说接之后是否再抽一次概率 |
| `fallback_chance` | 0.3 | 判官失败/超限/关闭时的兜底概率 |
| `daily_limit` / `cache_seconds` | 50000 / 3000 | 日 token 上限；同一条消息的判定缓存秒数 |
| `burst_enable` | true | 话段聚合总开关 |
| `burst_settle` | 3.5 | 判定前等这一口气说完的秒数 |
| `burst_gap` | 15 | 两条消息间隔小于它算同一段 |
| `burst_reuse` | 45 | 这一段判过/回过后不再送判官的秒数（省 token） |
| `reply_gap` | 6 | 回复真正发完后的静默秒数 |
| `inflight_ttl` | 45 | 判定通过到生成完的认领上限（失败兜底，防锁死） |
| `inflight_lock` | true | 在途硬锁：回复生成/分段发送期间，@ 它和唤醒前缀一律不接 |
| `dup_window` / `dup_ratio` | 45 / 0.75 | 相似去重窗口与阈值（0 即关闭） |
| `summon_gap` | 4 | 连叫名字的最小间隔 |
| `break_follow` | 30 | 带第二人称的脏话，往前看多少秒内它说过话才算在骂它 |
| `bot_names` | `["阿灰"]` | 叫到这些名字直接接，不吃冷却 |
| `break_words` | 见示例 | 脏话词表，命中只代表「让判官看一眼」，由判官判断在骂谁 |
| `ignore` / `force_reply` / `force_patterns` | 空 | 免打扰词 / 必答词 / 必答正则 |
| `followup_patterns` | 见示例 | 指向它的追问，0 token 直通 |

机制细节见上一节；本地模式（`local-llama`）不读这份文件，仍用 `data/judge.json` + 8082，话段聚合与在途硬锁也只在第三方模式生效。
